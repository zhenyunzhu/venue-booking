## 4. 设计说明：为什么这么写

### 4.1 为什么每个接口都包一层 `Result<T>`

不包的后果：接口 A 返回业务对象，接口 B 失败返回 `null`，接口 C 直接抛 500 让前端
看到一屏英文堆栈——前端只能到处 try-catch 和判空，联调鸡飞狗跳。
包一层之后，**失败也是结构化数据**：code 告诉前端"哪类问题"（1001 参数错弹表单红字、
1010 未登录跳登录页、2000 系统错误弹统一兜底框）。HTTP 状态码负责传输层语义，
code 负责业务语义，各管各的。

### 4.2 全局异常处理器如何消灭 try-catch

`@RestControllerAdvice` 本质是**所有 Controller 的 AOP 环绕通知**：任何 Controller
方法抛出的异常，先被这里的 `@ExceptionHandler` 按"最匹配类型"接住，翻译成 `Result`
再返回。于是业务代码变成了"快乐路径"：Service 里只管 `throw BizException.of(...)`。

日志分级是这里最容易被忽视但很关键的细节：
- `BizException` = 预期业务分支（库存不足），打 **warn 不带堆栈**——它不是事故，
  打堆栈只会制造日志噪音；
- 其他 `Exception` = 真事故，打 **error + 完整堆栈**——这是排查的唯一线索。
- 另外**绝不能把堆栈/内部异常信息返回给前端**（信息泄露），兜底只返回
  "系统繁忙" + 2000。

### 4.3 MyBatis-Plus 三插件，各对应一个事故剧本

- **分页插件**：MP 的分页是"拦截器改写 SQL 拼 LIMIT"。不配置，`Page` 查询不会拼
  LIMIT，把全表捞进内存再"假分页"——测试环境数据少看不出来，上线数据量一大
  直接 OOM。这是真实事故高发区。
- **乐观锁插件**：M4 扣库存的 version 方案靠它自动拼 `version=?`。
- **防全表插件**：没有 WHERE 的 update/delete 直接抛异常。宁可启动期报错，
  也不能在线上手滑 `delete` 全表。

### 4.4 User 实体的三个机关

- `@TableField(select = false)`：默认查询**不带出** password 列——从源头杜绝
  "顺手把整个实体序列化给前端"的密码泄露；需要密码的登录场景再显式查。
- `@TableLogic` + yml 全局配置：查询自动拼 `deleted=0`，删除变 UPDATE——
  数据可恢复、可审计，生产标配。
- `IdType.AUTO`：用户 ID 用库自增；订单号 M4 用雪花算法生成——为什么订单号
  不用自增？可被猜单号遍历、分库分表会冲突、且无时间信息。

### 4.5 BCrypt 为什么必须由代码生成

BCrypt 每次加密生成**随机盐**，同一个密码每次散列都不同；SQL 里手抄散列串，
一旦算法/盐格式与登录校验不一致，就是"永远登录不上"的灵异 bug。
另外 BCrypt 慢是有意的（抗暴力破解），所以它只用于密码，不用于其他字段。

### 4.6 依赖最小化

只引入 `spring-security-crypto` 拿 BCrypt，而不引入整套 `starter-security`：
后者会自动装配一整条过滤器链，所有接口默认 401，行为不可控。
M2 我们用拦截器自己实现 JWT 认证——"每个请求如何被鉴权"的完整链路完全可控，比直接引入 Spring Security 更轻量。

## 5. 环境踩坑复盘（版本升级引发的事故）

本次构建真实遇到并修复了两个**新版生态兼容问题**：

1. **JDK 23+ 默认关闭隐式注解处理** → Lombok 在 JDK 26 上"静默失效"，
   报错全是 `找不到符号 setPassword`。修复：maven-compiler-plugin 显式
   `<proc>full</proc>`，并把 Lombok 升到 1.18.48。
   排查思路：报错符号恰好都是 Lombok 该生成的成员 → 怀疑注解处理没跑 → 查
   JDK 变更记录 → 定位。**这个"报错特征→怀疑注解处理器"的推理链，是定位此类问题的通用方法。**
2. **MyBatis-Plus 3.5.9 起构件拆分** → `PaginationInnerInterceptor` 等依赖
   JSqlParser 的拦截器被移出 starter，需显式引入 `mybatis-plus-jsqlparser`。

经验教训一句话：**升级大版本 JDK/框架时，先跑一次全量编译，把"静默失效"类问题
在第一天才拦下来。**
